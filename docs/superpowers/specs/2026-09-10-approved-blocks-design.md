Product presentation stays viewing-first: readable files, excellent single images and carousels, safe useful video posters, playback, expansion and original downloads. No document editors, annotations, map platform, invented agent permissions, or social publishing integration are included.

## Design contract

Use Colony's existing semantic theme tokens in both light and dark appearance, including community accents and actual narrow thread container widths. Keep text on named rem-based tokens. Read-only cards do not look like editable forms. Use native shared components and optional bounded presentation fields, never a handle-specific HTML renderer. Preserve old immutable manifests and their trusted hashes.

Small tables omit redundant filtering and inactive sort chevrons; larger tables retain search/sort with readable numeric alignment, wrapped text and human booleans. Details displays useful facts and omits empty content. Blueprint presents people, teams, costs and numbered first work through card lists instead of five dense tables. Brief shows findings and sources. Receipt leads with the outcome and quieter reference disclosure. Interview shows position, purpose and known context, with a conversational answer and working unknown response. Choice question exposes schema-bound dynamic options and single/multi selection.

Images remain full-width singly and ordered carousels in groups, with thumbnails. Video/document collections show explicit filenames/posters and one selected viewer, pause replaced playback, retain each occurrence's lightweight position, and keep original download identity. Invalid and excessive entries must not silently disappear. Ordinary attachments and Block media should use the same viewer policy where their paragraph/message boundaries allow it.

Mermaid provides bounded flow, sequence and relationship diagrams as fenced source and .mmd/.mermaid attachments. Source is content, not executable configuration. Disable source-provided directives, callbacks and external resources; use a pinned bundled lazy dependency, serial theme rendering and declarative SVG output rendered as an image. Preserve source/download fallback on invalid or unavailable diagrams. Do not relax the existing SVG upload contract.

## Agent contract

Provide one discoverable describe operation that resolves the active trusted catalogue definition, examples, schema, actions and customization boundaries. Fix the generic Question demo limitation and Interview unknown-action input. Continue signed, instance/processor-scoped action validation and receipts. Ordinary agents do not activate catalogue definitions or receive arbitrary CSS/JavaScript abilities. Revised posted deliverables retain version history. Correct stale invocation examples rather than inventing new event transports.

## Proof gates

1. Implementation covers the entire inventory through shared components and real catalogue examples; no fake sample actions in product flows.
2. Focused contract checks and GitHub CI validate legacy manifests, dynamic selections, input wiring, safe diagrams, mixed file ordering/state and fallbacks. No local full CI, app builds, Rust compilation or broad test suites. Quick targeted installed-dependency checks are allowed.
3. GitHub-hosted browser tests render representative/composed blocks in light/dark channel/thread widths, capture every built-in block, exercise files and diagrams, and produce reviewable artifacts. Inspect results and fix defects before calling visual parity proven.
4. Develop PR and protected production promotion require all non-skipped applicable checks green. Coordinate the single release owner; do not interfere with the separate0.16.12 publication. Keep implementation, merge, publication, installed and authenticated proof distinct.
