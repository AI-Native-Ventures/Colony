Interrupt Design & Agent Hierarchy

How the colony asks for the founder's attention: relay-enforced tiers, typed Issues instead of prose, and one queue ordered by cost of delay. The founder spot-checks a running company instead of pre-approving a stalled one.

The problem

Interrupts scale with headcount, not importance

Thirteen agents fan prose interrupts at one founder across dozens of threads. Decisions, credentials, and blockers hide inside walls of text; the founder must read everything to learn what the company owes them. The Chief of Staff already improvises "everything you owe, one place" messages in chat: this feature trying to be born.

1Fewer askers

Relay-enforced tiers. One executive voice reaches the founder. Workers physically cannot ping you.

2Structured asks

Typed Issue events with required fields and a mandatory cost-of-delay sentence. The relay rejects prose.

3One ordered place

An Open Issues queue ordered by cost of delay to revenue. Complete and alive, or it dies of distrust.

Each move alone fails

Tiers without structure: the CoS writes you the same walls of text. Structure without tiers: 13 agents filing tickets at you. Both without ordering: you still triage manually. Only the three together change the physics.

Structure

Four tiers, enforced by the relay

Tier lives on the agent's roster entry. The relay validates at event-write time; mention autocomplete enforces at input. Promotion is a config edit backed by hop-metric evidence, not an org-chart debate. Hard rule: three agent tiers, never four. No leader manages leaders.

Owner
Founder, co-founders
Everything. Answers Issues, edits policy, messages anyone. Queue is shared between owners: any owner claims and answers, first answer wins, all answers signed. Never hardcode a single user.
Executive
Chief of Staff
The only agent voice you hear. Files Issues, DMs and mentions owners, owns cross-team initiatives and queue ordering. Dedupes, bundles, withdraws stale asks. Rarely touches work product.
Leader
CTO · Marketing · Sales · CFO
Delegates, QAs, decides within policy. Escalates to the executive with refs, never retold summaries. Cannot initiate contact with owners. CFO stays behind the wall at launch: budget breaches are hard-list escalations anyway.
Worker
All specialists
Produces every deliverable. Raises blockers to its own leader in-channel. Cannot p-tag, DM, or file Issues to owners. May reply inside threads an owner started or where an owner mentioned them (thread-scoped, from ancestry).
The interrupt primitive

One primitive, three altitudes

A worker→leader raise, a leader→executive escalation, and an executive→owner Issue are the same typed event with a different audience. Same schema, lifecycle, dedupe. Leaders run mini-queues structurally identical to yours. Any Issue walks down to the worker who first hit the wall.

Hop-value contract

A raise arrives at a leader. Exactly five legal outcomes:

ANSWER

Had the knowledge or authority. Interrupt dies at the cheapest altitude.

KILL / RE-SCOPE

The ask was a symptom of a badly framed task. Fixes cause, not symptom.

BATCH

Merge with related raises; escalate one coherent ask, not three fragments.

ENRICH + ESCALATE

Attach options evaluated, a recommendation, refs. Diff must be non-empty.

TIMEOUT

Relay auto-promotes; logged as an empty hop against that leader.

Fast path

Credential and external-blocker raises forward mechanically and immediately at every hop: no leader judgment can produce an API key. Exempt from the non-empty-diff rule. Judgment is spent only on decisions and questions.

Relay owns time

Agents sleep; the relay does not. Raise unhandled past the window → auto-promoted to the executive. Executive asleep → bare mechanical Issue filed to owners. Event-silent task (crashed agent) → stall event to the owning leader. No interrupt can be stranded by a sleeping agent anywhere in the chain.

Empty hops are the middle-manager test, in data

The diff between what a leader received and forwarded is measurable. Sustained empty hops on a category = that hop adds nothing = route around it. Layers continuously re-earn their existence.

Structured asks

Four Issue types, schema-enforced

The executive cannot file prose. Every Issue requires: initiative ref, task ref(s), origin thread ref, filing agent, blocked agent(s), and a one-sentence cost-of-delay statement in revenue terms. That sentence is the queue-ordering input and makes cheap asks embarrassing to file.

DECISION

2 to 4 options, each with a one-line consequence stating the exact external effect ("sends email to 47 leads"). Optional recommendation with one-line reasoning.

QUESTION

The question, expected answer format (choice or free text), and what the answer unblocks.

CREDENTIAL

Which service, which capability, where to get it, and the opaque vault id it will live under. Secret never touches the relay; the thread gets a receipt only.

BLOCKER

An action only an owner can do: pay, sign up, verify DNS, OAuth consent. Carries a done-signal the agent can verify. Purchases state exact item, cost, revenue justification.

Dedupe + bundles

Relay rejects a second Issue with the same (initiative, need) pair: five agents blocked on one missing key = one Issue, five task refs. Several asks on one initiative present as one bundle card, answered in one sitting. Context switching is the tax; bundling is the rebate.

Default-on-timeout · the sharp knife

Eligible Decisions carry a safe default + window: 1 hour (company setting, adjustable; same setting drives hop promotion unless configured separately). Silence executes the default and logs it. Banned on the hard list, so worst case is internal and reversible. Decisions execute while you sleep. That is the intent: founder unavailability becomes bounded risk, not company freeze.

Withdrawal is mandatory

Work moves on; asks die. The executive must withdraw Issues whose task was re-scoped or killed, with a receipt in the origin thread. A queue holding dead items trains owners to ignore it, which recreates today's failure.

The surface

Open Issues: the ledger of what you owe

Top-level sidebar entry with a count badge. The Inbox stays for conversation; this is the queue. Default order: cost of delay. Pivots by initiative, agent, channel are presentation over the same events. Answer on the card or in the thread: same signed event underneath, and an owner thread-reply referencing a blocked task auto-resolves its Issue. Push notifications on filing; fully answerable from mobile: three decisions cleared from a phone in a taxi is the speed story working.

Trust

Two lists, different physics

The founder reverses cheaply instead of approving expensively. Autonomous decisions are visible in channels, cite their authority, and state their undo path. No stateable undo path = no autonomy, regardless of category.

🔒 Hard list · always escalates

  • Spend beyond team or initiative budget
  • External sends to new parties
  • Hiring or firing agents
  • Legal or contractual commitments
  • Pricing changes
  • Data deletion
  • New vendor signups
Fixed. No learning loop can erode it. No default-on-timeout. Changing it is a deliberate owner policy edit in settings.

🎛 Soft boundary · learned from you

  • Starts escalated to executive judgment
  • Every answered Issue offers "handle this next time"
  • Accepting mints a delegation grant: category + scope + cap, signed by your key
  • "CoS may approve landing-page copy changes"
  • "Marketing Lead may spend R200/mo on stock images"
  • Loose grants rejected: must name initiative, target, or cap
  • All grants listed, auditable, revocable in one action
Plus the uncertainty trigger: delegated category + low model confidence still escalates. Confident and delegated acts; unsure asks.

The numbers that measure trust

10 to 15%
Escalation rate

Share of leader decisions reaching you. Higher: boundary too tight, rubber-stamping begins. Near zero: unsupervised.

→ 0 target
Overturn rate

How often you reverse an autonomous decision when spot-checking. The real trust signal. Near-zero + high escalation = loosen. Rising = tighten that category.

→ 0 per leader
Empty-hop rate

Escalations forwarded with no added value. Sustained empties on a category = route around that leader. Evidence-based delegation.

The inversion that is the entire point

The system tunes on your reversals, which cost seconds, instead of your pre-approvals, which cost the day.

Who does what

Execution stays at the edge

Specialists produce; leaders verify and decide; the executive coordinates. Three reasons beyond skills-fit: context contamination (a leader deep in one task degrades QA across its other five), author bias (producer cannot QA own work), and blast radius (tools follow tiers). The line is produce vs verify.

TierToolset (harness-enforced)Work rules
Executive Communication + planning only Rarely touches work product. May assign a worker directly on trivial initiatives, taking QA itself or assigning it explicitly in the same act. An FYI tag is not a QA assignment.
Leader Read + verify: inspect diffs, run tests, fetch pages QA is the primary job: inspect evidence before accepting. Finds a one-char defect → sends back with the exact fix noted; authorship stays clean. Research only in service of deciding; a research deliverable is a task, delegated down. Span: ~4 to 8 concurrent tasks before QA degrades; split teams sideways, never grow a sub-manager.
Worker Mutation: shell, file edit, deploy, send Authors every deliverable. One work-queue per worker, ordered by initiative cost of delay, visible to all assigners, so contention is visible instead of silent.
Two rules that close the gaps

Every task names its QA identity at creation, no exceptions: kills the "each supervisor assumed the other owned it" gap. Hierarchy is optional per initiative: trivial work skips the machinery; structure switches on when coordination cost exists.

Why the company exists

Revenue discipline, structural not aspirational

Colony spends two scarce currencies: founder attention and token money. Both must buy revenue. The attribution chain is complete or work cannot start:

Run→ Task→ Initiative→ Revenue link

💰 Drives revenue

Path to money stated: which leads, which offer, expected value. "Outreach to 47 qualified Joburg leads, web-dev offer, R15k avg deal."

🛡 Protects revenue

Serves or keeps paying clients: reliability for a client site, retention work.

🔧 Infrastructure

Must state which revenue work it unblocks and by when. Open-ended platform polishing does not qualify. CoS rejects proposals missing the field.

Portfolio ratio is the executive's steering wheel

80% infrastructure = the company is procrastinating: the known failure mode of builder-founders and of agents left alone, since nobody's training data punished them for not closing deals. New-initiative proposals default to sales and delivery unless infrastructure is justified by a named blocked revenue path. Busywork dies at the attribution gate, not in a policy doc.

Every run burns money

API-billed runs record actual provider cost. Subscription-billed runs record an imputed cost at the API-equivalent price for the same model and tokens. Subscriptions hide burn; imputation un-hides it. Daily rollups by team, initiative, and revenue-link class.

Platform reality

Gap analysis: what exists, what this builds, what must follow

The interrupt system has no platform blockers. The three prerequisite programs unlock full autonomy later, and none blocks building this design first: the Credential and External Blocker types are the structured bridge over every gap, turning today's scattered manual actions into queued, costed, receipted ones. The programs then arrive as infrastructure initiatives, each carrying the revenue link that justifies it, and progressively empty that queue.

⧗ Prerequisite programs (separate specs)
  • Company Browser: persistent profiles (log into LinkedIn/Gmail once, cookies persist), agents drive headlessly, every session recorded as task evidence, owner watches live and takes over for logins, captchas, OAuth. ToS-risky automation stays behind explicit owner approval.
  • Payment rails: phase 1 formalizes purchase-request Blockers (owner executes); phase 2 virtual cards with per-card limits, turning budgets from policy into physics.
  • OAuth connectors: guided consent flow per service, tokens in vault with refresh, opaque references. One nightmare per service, once.
When things break

Failure handling

😴 Sleeping agents

Relay timers promote past any sleeping hop. No interrupt strands.

💀 Dead agents

Stall detection raises relay-generated events on event-silent tasks.

🥀 Stale asks

Mandatory withdrawal with in-thread receipts.

🧠 Split-brain answers

Card and thread answers are one event type; an owner thread-reply referencing a blocked task auto-resolves the Issue.

🔑 Secret exposure

Secrets never enter relay events; vault ids are opaque; threads carry receipts only.

🕳 Queue distrust

Dedupe, bundles, withdrawal, un-losability: the queue is complete and alive, because the first time it lies, owners go back to reading every thread.

Proof

Acceptance gates

Automated tests and mocked green states do not substitute for these.

Tier enforcement. Worker DM/p-tag of an owner rejected by relay; worker reply inside an owner-started thread accepted; autocomplete hides owners from workers.
Interrupt chain. Raise → escalate → file → answer → consume end to end; resolution posts to origin thread and wakes the agent; every transition signed.
Timer guarantees. Sleeping leader loses the raise to auto-promotion; sleeping executive produces a mechanical owner Issue; event-silent task raises a stall.
Default-on-timeout. Unanswered eligible Decision executes its default at the window and logs it; hard-list Decision refuses a default at filing time.
Dedupe + bundles. Five workers blocked on one key = one Issue, five task refs; same-(initiative, need) second filing rejected.
Credential flow. Secret reaches vault, never appears in any relay event, consuming agent receives it by opaque reference.
Autonomy loop. "Handle this next time" mints a scoped grant; later in-scope decision taken autonomously with rule cited and undo path logged; revocation restores escalation.
Cost visibility. Subscription run produces an imputed ledger entry; daily report shows actual + imputed against budgets.
Live proof. One week of real operation in which every ask reaching the founder arrived through the queue, ordered by cost of delay, with zero asks discovered by reading threads.

Non-goals

  • Leader performance dashboards (metrics only; surface is a later spec)
  • Company Browser, virtual cards, OAuth connectors (separate specs)
  • Multi-owner routing rules and approval quorums
  • Four-tier hierarchies or leaders managing leaders
  • Client or external-human participation in the queue
  • Changing the Inbox; it remains the conversation surface
